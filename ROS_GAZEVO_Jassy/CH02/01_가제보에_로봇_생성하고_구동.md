# 01 가제보에 로봇 생성하고 구동하기

> 앞 장에서 우리는 URDF 파일을 작성하며 RViz2에서 로봇 모델을 완성했습니다. <br> 여기서는 이 URDF 파일을 이용해 Gazebo 가상 환경에 로봇을 생성하고, 물리 시뮬레이션을 위한 설정을 추가해 보겠습니다. <br>이어서 생성된 로봇을 직접 구동하며 주행 상태와 관절 정보를 확인하고, <br> 라이다·카메라 센서 데이터까지 RViz2로 시각화하며 로봇이 정상적으로 동작하는지 확인해 봅니다.

### 바퀴 속성 변경하기

다음은 바퀴를 구동하기 위한 토크와 속도를 실제 모터 사양에 맞춰 설정합니다. 또 가제보 시뮬레이션에서 바퀴 회전 시 마찰을 줄이기 위해 바퀴의 collision 속성을 cylinder에서 sphere로 변경합니다.

2. 계속해서 예제를 수정합니다.

**robot_core_diffdrive.xacro**

```xml
    <!-- LEFT WHEEL -->

    <joint name="left_wheel_joint" type="continuous">
        <parent link="base_link"/>
        <child link="left_wheel"/>
        <origin xyz="0 0.0907 0" rpy="-${pi/2} 0 0"/>
        <axis xyz="0 0 1"/>
        <limit effort="0.23" velocity="9.42"/>
    </joint>

    <link name="left_wheel">
        <visual>
            <geometry>
                <cylinder length="0.026" radius="0.0325" />
            </geometry>
            <material name="blue"/>
        </visual>
        <collision>
            <geometry>
                <!-- <cylinder length="0.026" radius="0.0325" /> -->
                <sphere radius="0.0325"/>
            </geometry>
        </collision>        
        <xacro:inertial_cylinder mass="0.06" length="0.026" radius="0.0325">
            <origin xyz="0 0 0" rpy="0 0 0"/>
        </xacro:inertial_cylinder>
    </link>

    <!-- RIGHT WHEEL -->

    <joint name="right_wheel_joint" type="continuous">
        <parent link="base_link"/>
        <child link="right_wheel"/>
        <origin xyz="0 -0.0907 0" rpy="${pi/2} 0 0"/>
        <axis xyz="0 0 -1"/>
        <limit effort="0.23" velocity="9.42"/>
    </joint>

    <link name="right_wheel">
        <visual>
            <geometry>
                <cylinder length="0.026" radius="0.0325" />
            </geometry>
            <material name="blue"/>
        </visual>
        <collision>
            <geometry>
                <!-- <cylinder length="0.026" radius="0.0325" /> -->
                <sphere radius="0.0325"/>
            </geometry>
        </collision>    
        <xacro:inertial_cylinder mass="0.06" length="0.026" radius="0.0325">
            <origin xyz="0 0 0" rpy="0 0 0"/>
        </xacro:inertial_cylinder>
    </link>
```

> 다음은 <limit> 태그로 Torque와 Velocity를 설정합니다. 이 부분에 대한 설정이 없으면 가제보 시뮬레이션 시 순간적으로 급격한 움직임이 발생할 수 있습니다. 

```xml
<limit effort="0.23" velocity="9.42"/>
```

**Velocity - 조인트의 회전 속도를 의미하며, 다음과 같이 구합니다.**

```
Velocity - 무부하 속도(90 RPM) 기준
<limit>은 "절대 넘을 수 없는 물리적 상한"을 의미하므로, 부하가 전혀 없을 때 낼 수 있는 최고 속도(무부하 속도)를 기준으로 잡습니다.
90 RPM → rad/s: 90 × 2π / 60 ≈ 9.42 rad/s
바퀴 반경 0.0325m 기준 선속도로 환산하면:
v = 9.42 × 0.0325 ≈ 0.31 m/s
```
Effort는 이 책에서 사용하는 N20 DC 모터의 사양을 기준으로 다음과 같이 구합니다.

![Collision 확인](../img/image131.bmp)

```
Effort — 정지 토크(2320 g·cm, 12V) 기준
먼저 g·cm를 N·m로 단위 변환을 하면
1 g·cm = 9.80665×10⁻⁵ N·m 입니다.
2320 g·cm × 9.80665×10⁻⁵ ≈ 0.2275 N·m
```
다음은 바퀴의 <collision> 속성을 <cylinder>에서 <sphere>로 변경합니다.

```xml
<sphere radius="0.0325"/>
```

> 이렇게 하면 가제보 시뮬레이션 시, 지면에 닿은 부분을 최소로 해서 차동 모션의 마찰로 인한 이상한 odometry issues를 줄일 수 있습니다. <br> 다만 sphere로 바꾸면, 접촉점이 사실상 하나뿐이라 그 지점을 축으로 한 회전(요 방향)에는 병진 마찰이 저항하지 못해, 정지 상태에서도 미세한 슬립이 발생할 수 있습니다.

3. 명령을 재구동합니다.

```

```

4. 다음과 같이 RobotModel에서 ➊ Visual Enabled 항목을 언체크하고, ➋ Collision Enabled 항목을 체크해 봅니다.

## 01_4 로봇 구동하기 (/cmd_vel, teleop_twist_keyboard)

먼저 로봇 구동을 위한 urdf 환경을 구성한 후, teleop_twist_keyboard 노드를 이용하여 로봇을 구동해 봅니다.

1. 파일을 수정합니다.

**robot.urdf.xacro**

```xml
<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro" name="robot">

    <xacro:include filename="robot_core_diffdrive.xacro" />
    <xacro:include filename="ros2_control_diffdrive_gz.xacro" />
    
</robot>
```

2. 파일을 작성합니다.

**ros2_control_diffdrive_gz.xacro**

```xml
<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro">

  <ros2_control name="myros_diffdrive" type="system">
    <hardware>
      <plugin>gz_ros2_control/GazeboSimSystem</plugin>
    </hardware>

    <joint name="left_wheel_joint">
      <command_interface name="velocity"/>
      <state_interface name="position"/>
      <state_interface name="velocity"/>
    </joint>
    <joint name="right_wheel_joint">
      <command_interface name="velocity"/>
      <state_interface name="position"/>
      <state_interface name="velocity"/>
    </joint>
  </ros2_control>

  <gazebo>
    <plugin name="gz_ros2_control::GazeboSimROS2ControlPlugin"
            filename="libgz_ros2_control-system">
      <parameters>/root/myros_sketch/diffdrive_controllers.yaml</parameters>
    </plugin>
  </gazebo>

</robot>
```

> 이 코드의 핵심은 로봇의 바퀴 조인트(Joint)를 ros2_control 프레임워크에 등록하고, 이를 Gazebo 시뮬레이션 환경 내의 시뮬레이션 플러그인과 연결하는 역할을 합니다.

**ros2_control 태그 영역**: 로봇의 하드웨어(또는 시뮬레이션 하드웨어)와 ROS 2 제어기(Controller) 사이의 인터페이스를 정의합니다.

- `name="myros_diffdrive"`: 이 제어 시스템의 이름
- `type="system"`: 여러 조인트를 통째로 제어하는 "System" 타입
- `<plugin>gz_ros2_control/GazeboSimSystem</plugin>`: Gazebo 시뮬레이터를 가상의 하드웨어로 사용하겠다고 선언하는 하드웨어 인터페이스 플러그인

```bash
find /opt/ros/jazzy/ -name libgz_hardware_plugins.so
```

- `<command_interface name="velocity"/>`: 속도(Velocity) 명령을 전달받도록 설정
- `<state_interface name="..."/>`: 시뮬레이터로부터 바퀴의 현재 속도와 위치(회전각) 피드백을 받아 전달

**Gazebo 플러그인 태그 영역**: Gazebo 시뮬레이터가 실행될 때 ros2_control 노드를 함께 로드하도록 연결

```bash
find /opt/ros/jazzy/ -name libgz_ros2_control-system.so
```

3. 파일을 작성합니다.

**diffdrive_controllers.yaml**

```yaml
controller_manager:
  ros__parameters:
    update_rate: 100

    joint_state_broadcaster:
      type: joint_state_broadcaster/JointStateBroadcaster

    diff_drive_controller:
      type: diff_drive_controller/DiffDriveController

diff_drive_controller:
  ros__parameters:
    left_wheel_names: ["left_wheel_joint"]
    right_wheel_names: ["right_wheel_joint"]

    wheel_separation: 0.1814
    wheel_radius: 0.0325

    position_feedback: false
    open_loop: false

    base_frame_id: base_footprint
    odom_frame_id: odom
    enable_odom_tf: true

    cmd_vel_timeout: 0.5
    
    linear.x.max_velocity: 0.306
    linear.x.min_velocity: -0.306
    angular.z.max_velocity: 3.38
    angular.z.min_velocity: -3.38
```

### Controller Manager 설정 (controller_manager)

- `update_rate: 100`: controller_manager 자체의 제어 루프 주기. 초당 100번 모든 활성 컨트롤러의 update()를 호출.
- `joint_state_broadcaster`: JointStateBroadcaster 클래스 등록
- `diff_drive_controller`: DiffDriveController 클래스 등록

### 차동 구동 제어기 상세 설정 (diff_drive_controller)

**① 조인트 및 규격 설정**

- `left_wheel_names / right_wheel_names`: 좌/우 바퀴 관절 이름 매핑
- `wheel_separation: 0.1814`: 윤거(0.1814m = 18.14cm)
- `wheel_radius: 0.0325`: 바퀴 반지름(3.25cm)

**② 제어 방식 설정**

- `position_feedback: false`: 속도(Velocity) 피드백 사용
- `open_loop: false`: 피드백을 사용하여 오도메트리 계산

| 조합 | 오도메트리 계산 방식 | 특징 |
|---|---|---|
| open_loop: true | cmd_vel 명령값만으로 계산 | 로봇이 끼어 있어도 RViz는 명령대로 주행 |
| open_loop: false / position_feedback: true | position(누적 각도) 센서 값으로 계산 | position state 구현 필요 |
| open_loop: false / position_feedback: false | velocity(현재 속도) 센서 값으로 계산 | velocity state 데이터 필수 |

**③ 위치 추정 (Odometry)**

- `base_frame_id / odom_frame_id`: odom 좌표계 기준으로 base_footprint 위치 추적
- `enable_odom_tf: true`: odom → base_footprint TF 자동 생성

**④ 안전 및 속도 제한 설정**

- `cmd_vel_timeout: 0.5`: 0.5초 동안 /cmd_vel 명령이 없으면 자동 정지
- `linear.x.*`: 직진/후진 최대 선속도 0.306m/s
- `angular.z.*`: 회전 최대 각속도 ±3.38rad/s

> 최대 선속도 계산: 90RPM → 1.5RPS → `1.5 × 2 × π × 0.0325m = 0.306m/s`
> 제자리 회전 최대 각속도: `0.306 × 2 / 0.1814 = 3.38rad/s ≈ 193°/s`

4. 파일을 작성합니다.

**gz_bridge.yaml**

```yaml
# Clock needed so ROS understand's Gazebo's time
- ros_topic_name: "clock"
  gz_topic_name: "clock"
  ros_type_name: "rosgraph_msgs/msg/Clock"
  gz_type_name: "gz.msgs.Clock"
  direction: GZ_TO_ROS
```

| 필드 | 값 | 의미 |
|---|---|---|
| ros_topic_name | "clock" | ROS2 쪽 토픽 이름 → /clock |
| gz_topic_name | "clock" | Gazebo Transport 쪽 원본 토픽 이름 |
| ros_type_name | "rosgraph_msgs/msg/Clock" | ROS2 메시지 타입 |
| gz_type_name | "gz.msgs.Clock" | Gazebo 쪽 원본 메시지 타입 |
| direction | GZ_TO_ROS | Gazebo에서 ROS2로만 흐름 |

> 1. Gazebo가 clock 토픽을 발행 → 2. ros_gz_bridge가 /clock으로 변환 → 3. use_sim_time:=true로 설정된 모든 ROS2 노드가 이 /clock을 구독해 시뮬레이션 시간으로 맞춤.

5. 6개의 명령창을 준비합니다.

![명령창 준비](../img/image126.bmp)

> ※ 바로 다음에 이 6개의 명령창을 이용하여 다음 명령들을 수행하며 실습을 진행합니다.

```
① ros2 run robot_state_publisher robot_state_publisher --ros-args -p robot_description:="$(xacro /root/myros_sketch/robot.urdf.xacro)" -p use_sim_time:=true
② gz sim -r -v4 empty.sdf 
③ ros2 run ros_gz_bridge parameter_bridge --ros-args -p config_file:=/root/myros_sketch/gz_bridge.yaml
④ ros2 run ros_gz_sim create -topic robot_description -name my_bot -z 0.1
⑤ ros2 run controller_manager spawner joint_state_broadcaster
⑥ ros2 run controller_manager spawner diff_drive_controller
⑦ xterm -e ros2 run teleop_twist_keyboard teleop_twist_keyboard \

```

> ④,⑤,⑥ 명령은 다음과 같이 &&로 묶어서 한 번에 실행합니다.

```
④+⑤+⑥

ros2 run controller_manager spawner joint_state_broadcaster && \
ros2 run controller_manager spawner diff_drive_controller
```

## 01_5 가제보와 Rviz2 연동 테스트

## 01_10 카메라 구동하기

다음은 카메라 구동을 위한 urdf 환경을 구성해 봅니다.

1. 예제를 수정합니다.

**robot.urdf.xacro**

```xml
<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro"  name="robot">

    <xacro:include filename="robot_core_diffdrive.xacro" />
    <xacro:include filename="ros2_control_diffdrive_gz.xacro"/>
    <xacro:include filename="lidar.xacro"/>
```

2. 예제를 작성합니다.

**camera.xacro**

```xml
<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro">

    <gazebo reference="camera_link">
        <sensor name="camera" type="camera">
            <pose> 0 0 0 0 0 0 </pose>
            <visualize>true</visualize>
            <update_rate>10</update_rate>
            <camera>
                <camera_info_topic>camera/camera_info</camera_info_topic>
                <horizontal_fov>1.089</horizontal_fov>
                <image>
                    <format>R8G8B8</format>
                    <width>640</width>
                    <height>480</height>
                </image>
                <clip>
                    <near>0.05</near>
                    <far>8.0</far>
                </clip>
            </camera>
            <topic>camera/image_raw</topic>
            <gz_frame_id>camera_link_optical</gz_frame_id>
        </sensor>
    </gazebo>

</robot>
```

```yaml
# Camera topics (main camera data handled by dedicated image bridge)

  gz_topic_name: "camera/camera_info"
  ros_type_name: "sensor_msgs/msg/CameraInfo"
  gz_type_name: "gz.msgs.CameraInfo"
  direction: GZ_TO_ROS
```
